# 协作模型

## 1. 好友与私聊

- 双方通过账号添加好友。
- 好友之间可以私聊。
- 私聊消息使用独立 `thread_key` 保存，不进入任务沟通线程和管理端消息中心。
- 聊天窗内可以直接转发任务。

## 2. 共享 vs 转交

### 共享协作

A 把任务共享给 B：

1. 生成一条待处理邀请。
2. B 接受后，服务端为 B 创建任务副本。
3. 两边任务 ID 不同，但拥有同一个 `share_group_id`。
4. 双方都保留任务，继续共同推进。

### 转交任务

1. A 把任务转交给 B。
2. B 接受后，任务归 B。
3. A 原任务归档。
4. 不建立共享组，后续不双向同步。

## 3. 全字段同步

共享任务保存时，以下字段写回同一 `share_group_id` 的所有副本：

- 标题
- 任务要求
- 周期
- 开始时间 / 截止时间
- 负责人 / 负责人账号
- 进度
- 完成状态
- 流失状态 / 流失时间 / 流失原因
- 子任务
- 标签
- 任务记录

每次保存后 `revision` 加一。

## 4. 编辑流程

```text
A 点击编辑
  → 服务端加锁
  → A 修改并保存
  → 全字段写回所有副本
  → revision + 1
  → A 关闭编辑器，释放锁

B 点击编辑
  → 服务端尝试加锁
  ├─ A 仍在编辑：409「A 账户编辑中，请稍后更新重试」
  └─ 锁已释放：
       → 比较本地 revision 与服务端 revision
       ├─ 一致：进入编辑器
       └─ 不一致：释放锁，提示
            「任务已更新，请先点状态更新后再编辑」
```

B 点击「状态更新」后：

- 拉取最新字段
- 更新本地 revision
- 再次编辑即可看到 A 保存的最新内容

## 5. 服务端版本保护

共享任务更新端点会校验：

```text
base_revision == 服务端当前 revision
```

不一致时拒绝写入，避免 B 的旧副本覆盖 A 的新内容。

## 6. 管理端汇聚

管理端任务池按以下顺序合并：

1. 相同 `share_group_id`：必定合并。
2. 无共享组：标题去掉括号客户名、通用词后，跨账户相似度达到阈值才合并。
3. 合并后保留 `participants` 和 `copy_count`。
4. 统计、完成率、成员负载按合并后的数量计算。

## 7. 同步时机

- 客户端保存共享任务：立即写入共享更新端点。
- 客户端普通任务：保存本地，等待手动同步。
- 客户端「状态更新」：拉取服务端最新数据。
- 管理端「主动更新任务」：通知在线客户端推送任务并合并。
- 客户端心跳：10 秒一次，只做在线/收取检查，不重建任务页。

## 8. 当前边界

- 不是实时协同编辑，采用“编辑锁 + 版本校验”。
- 管理端汇聚的标题相似度合并属于启发式，极端同名项目需要人工确认。
- 共享任务删除策略按各端任务删除逻辑执行，历史消息仍保留。
